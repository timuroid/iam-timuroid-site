# Работа с проектом на компьютере и в облаке

Основной репозиторий: [timuroid/iam-timuroid-site](https://github.com/timuroid/iam-timuroid-site). GitHub хранит исходники и историю изменений; на компьютере и в облачном Codex работают отдельные копии этого репозитория. Изменения между ними передаются через Git.

## Первый запуск на компьютере

1. Установи Git и **Node.js 24 LTS**. Эта версия нужна серверу для встроенной SQLite. Проверь установки:

```bash
git --version
node --version
npm --version
```

2. Настрой доступ к GitHub. Можно использовать GitHub Desktop, `gh auth login` из GitHub CLI или собственный SSH-ключ GitHub. Для HTTPS GitHub использует авторизацию через браузер/менеджер учётных данных либо токен; пароль от аккаунта не заменяет токен. Доступ должен быть именно к этому репозиторию.

3. Склонируй проект в удобный каталог:

```bash
git clone https://github.com/timuroid/iam-timuroid-site.git
cd iam-timuroid-site
npm ci
```

Если выбран SSH-доступ к GitHub, адрес для клонирования — `git@github.com:timuroid/iam-timuroid-site.git`.

4. В приложении Codex на компьютере добавь проект и выбери **уже склонированную папку `iam-timuroid-site`**. Названия элементов интерфейса могут различаться между версиями приложения. Важен выбор этой папки: Codex должен видеть `package.json`, `README.md` и `AGENTS.md` в её корне. Можно давать обычные задания, например: «Измени описание моего опыта в `content/site.json`, затем проверь и собери сайт».

5. Скопируй `.env.example` в `.env` через редактор или файловый менеджер. В терминале macOS/Linux/Git Bash:

```bash
cp .env.example .env
```

В PowerShell:

```powershell
Copy-Item .env.example .env
```

Заполни `OPENAI_API_KEY` в локальном `.env`, если нужно проверять реального агента и голос. Ключ вводи в редакторе, не вставляй в команды или сообщения Codex. `.env` исключён из Git. Без ключа сайт, проекты и форма работают; функции OpenAI сообщают, что агент пока не подключён.

6. Проверь и запусти сайт:

```bash
npm run check
npm run dev
```

Открой **http://127.0.0.1:4173**. Перед запуском `npm run dev` автоматически выполняет сборку. Сервер читает `.env`, если файл существует, и переменные своего окружения. Остановить его можно через `Ctrl+C`. После правок текста, HTML или серверного кода снова выполни `npm run build` в другом терминале и обнови страницу: отдельного сборщика с автоматической пересборкой здесь нет. CSS и JavaScript интерфейса сервер разработки читает с диска.

Все адреса в этом разделе относятся к локальному компьютеру, на котором открыт проект.

После изменения `.env`, переменных окружения или самого `scripts/dev.mjs` останови сервер и запусти `npm run dev` снова.

Для проверки Node-сервера локально:

```bash
npm start
```

`npm start` тоже предварительно собирает проект. Сервер доступен по **http://127.0.0.1:3000**; адрес и порт задаются `HOST` и `PORT`. Для применения новых правок этот сервер нужно перезапустить. Локальная база разработки хранится в `.sites-runtime/preview.sqlite`, база Node-сервера по умолчанию — `data/timuroid.sqlite`. Это данные конкретной среды, они не синхронизируются через Git. Миграции применяются при запуске автоматически. Для микрофона браузер разрешает `localhost`/`127.0.0.1`; на опубликованном сайте нужен HTTPS.

## Где менять сайт

| Файл | Что в нём находится |
| --- | --- |
| `content/site.json` | Тексты, опыт, исследования, кейсы, контакты и знания агента |
| `public/index.html` | Структура страницы и панелей |
| `public/styles.css` | Цвета, типографика, адаптивность и оформление |
| `public/app.js` | Навигация, карточки, фильтры и форма |
| `public/orb.js` | Живой шар, отражения, частицы и реакция на взаимодействие |
| `public/agent.js` | Чат, голосовой разговор и состояние агента |
| `public/dictation.js` | Диктовка контактной формы |
| `public/` | Изображения, шрифты и другие материалы сайта |
| `content/logo-sources.json` | Источники логотипов |
| `server/worker.mjs` | API, запросы к OpenAI и сохранение заявок |
| `server/node.mjs` | Node-сервер и SQLite |
| `db/schema.ts`, `drizzle/` | Схема базы и миграции |
| `deploy/` | Шаблоны для публикации приложения |

`dist/` создаётся сборкой. Править его вручную не нужно: следующая сборка заменит результат. Секреты не должны попадать в `public/`, `content/`, историю Git или описание задач. Модели OpenAI меняются серверными переменными `OPENAI_TEXT_MODEL` и `OPENAI_REALTIME_MODEL`; пример значений есть в `.env.example`.

## Работа в облачном Codex

Подключи свой GitHub к облачному Codex и разреши доступ к **`timuroid/iam-timuroid-site`**. Выбери этот репозиторий и нужную ветку при создании задачи/среды. Это отдельная копия: несохранённые изменения с компьютера в неё не попадут.

Для среды выбери Node.js 24. Команды подготовки и проверки:

```bash
npm ci
npm run check
npm run build
```

Если облачная среда предоставляет предварительный просмотр приложения, запусти `npm run dev`. При необходимости задай `HOST=0.0.0.0` и нужный `PORT` через настройки среды: по умолчанию сервер слушает только `127.0.0.1:4173`.

Для работы над интерфейсом ключ OpenAI не нужен. Если облачная среда поддерживает серверные переменные/секреты для запуска приложения, задай `OPENAI_API_KEY` через её настройки; не сохраняй его в репозитории или тексте задания. У разных облачных сред область доступности секретов отличается: секрет только для подготовки среды не будет автоматически доступен позже запущенному серверу. Проверка реальных функций OpenAI требует передачи ключа именно в процесс сервера.

Задача Codex должна завершаться коммитом в отдельной ветке или pull request. Перед переносом работы на компьютер убедись, что ветка уже отправлена на GitHub. `AGENTS.md` в корне задаёт общие правила для локального и облачного Codex.

## Передавать работу между компьютером и облаком

Для каждой задачи используй отдельную ветку. Перед новой задачей обнови `main`, находясь в чистом рабочем каталоге:

Перед первым коммитом на новом компьютере Git может попросить указать имя и email автора через `git config user.name` и `git config user.email`. Используй свои данные или GitHub noreply-адрес.

```bash
git status
git switch main
git pull --ff-only origin main
git switch -c feat/update-career
```

После правок проверь сайт, просмотри изменения и отправь ветку:

```bash
npm run check
npm run build
git diff
git add content/site.json
git commit -m "Update career description"
git push -u origin feat/update-career
```

В `git add` перечисляй файлы своей задачи; команда выше — пример для описания опыта. Перед коммитом проверяй `git status`: там не должно быть ключей, локальной базы или файлов с паролями. На GitHub создай pull request в `main`; после проверки и слияния обе среды обновляются командой `git pull --ff-only origin main` на ветке `main`.

Если нужно продолжить **ещё не слитую** задачу в другой среде, сначала отправь её ветку, затем во второй копии выполни:

```bash
git fetch origin
git switch --track origin/feat/update-career
```

Если локальная ветка с этим именем уже есть, используй `git switch feat/update-career` и `git pull --ff-only`. В облачном Codex выбери эту ветку при запуске задачи. На время передачи останови изменения этой ветки в первой среде. Для одновременной независимой работы используй разные ветки; изменения одних файлов лучше выполнять последовательно.

Если `pull --ff-only` сообщает о расхождении истории, сохрани свою работу коммитом и попроси Codex разобраться с конфликтом. Не используй `push --force` или `reset --hard` для обычной синхронизации.

## GitHub и публикация

Отправка кода на GitHub сохраняет проект, но **не обновляет работающий сайт автоматически**. В репозитории нет настроенного автоматического развёртывания.

Для публикации приложения используй проверенную версию кода и настройки выбранного хостинга. Общие рекомендации находятся в [deploy/README.md](../deploy/README.md). Данные доступа и фактические параметры инфраструктуры сохраняй в закрытой документации, отдельно от публичного репозитория.

Метаданные прежнего Sites-проекта сохранены для совместимости. Основное место ведения кода теперь GitHub. Для работы с GitHub и локального запуска подключение к прежнему Sites-проекту не требуется.
