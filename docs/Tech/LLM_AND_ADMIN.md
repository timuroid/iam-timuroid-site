# Агент и панель владельца

## Что получает модель

`content/agent-prompts.json` — источник текста основных промптов: знакомство,
интервью, формат текстового ответа и порядок шести вопросов. `server/worker.mjs`
добавляет `content/site.json`, расширенные знания из `content/agent-knowledge.json`,
текущую страницу и подтверждённый черновик. В голосовом интервью к исходным
знаниям добавляются вопросы интервью. Навигация — по явной просьбе посетителя. Карта разделов в расширенных знаниях
описывает порядок, названия и видимые цвета на компьютере и телефоне. При
неоднозначном описании блока агент уточняет выбор. Голосовые инструменты
открывают разделы, карточки опыта, страницу кейса и его части, контакты и
страницу о данных. Простое знакомство не запускает сбор контактов; явное
прощание вызывает end_conversation: после короткого аудиоответа клиент закрывает
микрофон и сессию.

Расширенные описания не включаются в публичные HTML/assets. Это контекст модели,
а не место для секретов. У каждого проекта есть confirmed_description и
пустое additional_context для следующей итерации с владельцем. Факты/эффект
добавляются после подтверждения; демонстрационные сценарии отмечены явно.

В `/admin` → «Промпты и модели» видны исходные и собранные инструкции,
вопросы, фактические модели/голос/VAD и определения всех инструментов.
«Знания о проектах» показывает публичный и расширенный контекст.
Изменения выполняются в исходниках, затем обновляется выпуск.

## Интервью и хранение

Порядок: имя → контакт → задача → текущий процесс → желаемый результат →
ограничения. Дополнительные три пункта можно пропустить по ответу посетителя.
Агент записывает новое через prepare_contact_request в редактируемую форму;
сам её не отправляет. Очистка удаляет выбранное поле/весь черновик,
прикреплённый текст интервью и согласие. Отмена оставляет черновик.

До отправки поля и реплики находятся в памяти текущей вкладки.
После ручного согласия и submit `/api/leads` сохраняет:

- обычные поля заявки;
- interview_json: process, goal, constraints;
- conversation_json: до 40 реплик интервью, до 3000 символов каждая;
- review_status: new/read/archived.

Все текстовые диалоги и полученные расшифровки голоса теперь записываются
отдельно от заявок. Аудиофайлы в SQLite сайта не записываются. Текст/аудио для ответа
передаются OpenAI. Уведомлений нет. Админка показывает бриф и текст интервью,
позволяет пометить заявку, архивировать её и выгрузить JSON. Архивирование
обратимо; операции удаления сохранённых заявок в интерфейсе нет.

Миграция `0001_interview_admin.sql` добавляет поля с пустыми значениями
и таблицу admin_sessions; прежние заявки остаются доступными. Runtime применяет
SQL по имени один раз через __site_migrations. Перед обновлением нужен backup.

## Фрагменты на вершинах

`public/orb-tokens.js` получает реальные delta-события ответа/расшифровки,
а также текст отправленного вопроса. Длинные части разбиваются до шести символов.
Это фрагменты полученного текста, не внутренние BPE ID или рассуждения модели.
Расшифровка входа может поступать после окончания фразы; если delta нет,
используется завершённый текст. Completion не повторяет уже показанный stream.

Очередь ограничена 32 фрагментами, 10 подписями и 64 идентификаторами потоков.
Подписи появляются/затухают внутри общего Canvas; новые DOM-элементы и запросы
к модели не создаются. Маленький dock не рисует нечитаемые подписи. Reduced motion
показывает текст статично; завершение голоса очищает очередь. Аудиопакеты не
вызывают перерасчёт UI. Это не точная синхронизация каждого слова с воспроизведением.

## Доступ

Панель обслуживается `server/node.mjs` / `server/admin.mjs`.
Настройки: ADMIN_LOGIN (по умолчанию timuroid), ADMIN_PASSWORD_HASH
в формате `scrypt:<32 hex salt>:<128 hex digest>`. При пустом хеше вход отключён.
Файлы секретов исключены из Git; пароль/API-ключ в панели не отображаются.
Данные первого настроенного входа находятся в локальном
`project_files/admin-access.txt`, права 600. На сервер передаётся только хеш.

Сессия на 12 часов хранится в SQLite как SHA-256 токена. HTTPS cookie:
`__Host-timuroid_admin`, HttpOnly, Secure, SameSite=Strict, Path=/.
Локальный HTTP использует другое имя cookie. POST проверяет Origin,
изменения/выход — X-CSRF-Token. Пять неудачных входов за 15 минут ограничиваются
по IP. API возвращает no-store; выход отзывает серверную сессию.

Без входа `/admin` показывает только форму входа; `/api/admin/spec` и заявки
возвращают 401. `npm run check:admin` проверяет доступ, хранение, CSRF и миграцию
на отдельной базе. Production-проверка не создаёт пробных заявок.

## Все диалоги и анонимные сессии — 2026-10-03

`server/conversations.mjs` подключён в production Node и локальный preview.
Миграция `0002_visitor_conversations.sql` добавляет visitor_sessions и
conversation_messages. Drizzle schema, snapshot и journal синхронизированы.
Данные живут в прежней SQLite вне выпуска и входят в backup CI/CD.
Исторические несохранённые разговоры восстановить нельзя.

- POST `/api/conversations/start`: новая сессия, страница, устройство, User-Agent.
- POST `/api/conversations/message`: текст/расшифровка, роль, канал, event ID;
  visitor cookie должен принадлежать указанной сессии. Публичного чтения нет.
- POST `/api/conversations/end`: время завершения; сворачивание не завершает сессию.
- `/api/chat`: запрос и фактический ответ сохраняются на сервере независимо от
  того, успел ли браузер показать ответ. Повторный event ID обновляет запись.
- Голос: клиент сохраняет полученные расшифровки, действия и ошибки. Deltas
  объединяются и периодически сохраняются; финальный текст заменяет фрагмент.
  Поздний partial не заменяет финал. Неполная расшифровка помечена в админке.
  Неполученный браузером текст/звук после аварийного отключения восстановить нельзя.

Cookie `__Host-timuroid_visitor` (локально другое имя) случайный, HttpOnly,
Secure на HTTPS, SameSite=Lax, до года. База хранит SHA256, панель показывает
короткий анонимный ID. IP не сохраняется. Разные браузеры/очистка cookie дают
разных посетителей; совпадение ID не является доказательством личности.

`public/conversation-log.js` сериализует создание сессий, сохраняет outbox в
sessionStorage, повторяет после сетевых сбоев, использует keepalive на уходе.
Одна сессия объединяет чат/голос и навигацию; завершение начинает новую.
Реплики более 30000 символов разбиваются для доставки. Нет лимита числа
диалогов/реплик или автоматического удаления. Следить за ростом диска.
Содержимое Browser voice logs — клиентская расшифровка, не проверенная сервером
аудиозапись; source явно указан в JSON.

Админка «Все диалоги»: поиск по тексту, фильтр посетителя, все его сессии,
хронология, канал/модель/время, JSON export. Список по 50 сессий, реплики по
200 с продолжением; export включает историю. Для чтения нужна admin cookie,
no-store и существующая защита входа. Обычным посетителям истории других
пользователей не передаются. В интерфейсе используется textContent, не HTML.
Страница «О данных» и подпись в агенте сообщают о хранении текста.

## Модели

Текстовый API: `gpt-6-luna`, Chat Completions, `reasoning_effort: none`,
`max_completion_tokens: 2048`, прежняя строгая JSON schema действий.
OPENAI_TEXT_MODEL может переопределить значение. Реальные запросы проекта
к Luna подтвердили обычный ответ и навигацию show_section/cases.
Документация: https://developers.openai.com/api/docs/models/gpt-6-luna.
Luna не принимает/не генерирует аудио. Голос остаётся специализированным
`gpt-realtime`, Cedar, без изменения VAD/очереди; распознавание
`gpt-4o-mini-transcribe`. Эти имена доступны в панели как фактическая конфигурация.

Проверки: 44 состояния агента, параметры Luna/запись server response,
10 сценариев admin и 16 сценариев анонимных сессий, доступа, поиска,
пагинации, partial/final и повторной отправки outbox. Эти проверки не
доказывают физический микрофон/WebRTC или визуальный результат iPhone.
