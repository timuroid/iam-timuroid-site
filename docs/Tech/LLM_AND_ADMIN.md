# Агент и панель владельца

## Что получает модель

`content/agent-prompts.json` — источник текста основных промптов: знакомство,
интервью, формат текстового ответа и порядок шести вопросов. `server/worker.mjs`
добавляет `content/site.json`, расширенные знания из `content/agent-knowledge.json`,
текущую страницу и подтверждённый черновик. В голосовом интервью к исходным
знаниям добавляются вопросы интервью. Навигация — по явной просьбе посетителя.

Расширенные описания не включаются в публичные HTML/assets. Это контекст модели,
а не место для секретов. У каждого проекта есть confirmed_description и
пустое additional_context для следующей итерации с владельцем. Факты/эффект
добавляются после подтверждения; демонстрационные сценарии отмечены явно.

В `/admin` → «Промпты и модели» видны исходные и собранные инструкции,
вопросы, фактические модели/голос/VAD и определения всех инструментов.
«Знания о проектах» показывает публичный и расширенный контекст.
Изменения выполняются в исходниках, затем обновляется выпуск.

## Интервью и хранение

Порядок: имя → контакт → задача → текущий процесс → желаемый результат →
ограничения. Дополнительные три пункта можно пропустить по ответу посетителя.
Агент записывает новое через prepare_contact_request в редактируемую форму;
сам её не отправляет. Очистка удаляет выбранное поле/весь черновик,
прикреплённый текст интервью и согласие. Отмена оставляет черновик.

До отправки поля и реплики находятся в памяти текущей вкладки.
После ручного согласия и submit `/api/leads` сохраняет:

- обычные поля заявки;
- interview_json: process, goal, constraints;
- conversation_json: до 40 реплик интервью, до 3000 символов каждая;
- review_status: new/read/archived.

Обычный чат и аудиофайлы в SQLite сайта не записываются. Текст/аудио для ответа
передаются OpenAI. Уведомлений нет. Админка показывает бриф и текст интервью,
позволяет пометить заявку, архивировать её и выгрузить JSON. Архивирование
обратимо; операции удаления сохранённых заявок в интерфейсе нет.

Миграция `0001_interview_admin.sql` добавляет поля с пустыми значениями
и таблицу admin_sessions; прежние заявки остаются доступными. Runtime применяет
SQL по имени один раз через __site_migrations. Перед обновлением нужен backup.

## Фрагменты на вершинах

`public/orb-tokens.js` получает реальные delta-события ответа/расшифровки,
а также текст отправленного вопроса. Длинные части разбиваются до шести символов.
Это фрагменты полученного текста, не внутренние BPE ID или рассуждения модели.
Расшифровка входа может поступать после окончания фразы; если delta нет,
используется завершённый текст. Completion не повторяет уже показанный stream.

Очередь ограничена 32 фрагментами, 10 подписями и 64 идентификаторами потоков.
Подписи появляются/затухают внутри общего Canvas; новые DOM-элементы и запросы
к модели не создаются. Маленький dock не рисует нечитаемые подписи. Reduced motion
показывает текст статично; завершение голоса очищает очередь. Аудиопакеты не
вызывают перерасчёт UI. Это не точная синхронизация каждого слова с воспроизведением.

## Доступ

Панель обслуживается `server/node.mjs` / `server/admin.mjs`.
Настройки: ADMIN_LOGIN (по умолчанию timuroid), ADMIN_PASSWORD_HASH
в формате `scrypt:<32 hex salt>:<128 hex digest>`. При пустом хеше вход отключён.
Файлы секретов исключены из Git; пароль/API-ключ в панели не отображаются.
Данные первого настроенного входа находятся в локальном
`project_files/admin-access.txt`, права 600. На сервер передаётся только хеш.

Сессия на 12 часов хранится в SQLite как SHA-256 токена. HTTPS cookie:
`__Host-timuroid_admin`, HttpOnly, Secure, SameSite=Strict, Path=/.
Локальный HTTP использует другое имя cookie. POST проверяет Origin,
изменения/выход — X-CSRF-Token. Пять неудачных входов за 15 минут ограничиваются
по IP. API возвращает no-store; выход отзывает серверную сессию.

Без входа `/admin` показывает только форму входа; `/api/admin/spec` и заявки
возвращают 401. `npm run check:admin` проверяет доступ, хранение, CSRF и миграцию
на отдельной базе. Production-проверка не создаёт пробных заявок.
