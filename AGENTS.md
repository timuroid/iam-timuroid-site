# Работа над TIMUROID

Основной репозиторий: https://github.com/timuroid/iam-timuroid-site. Проект поддерживается в локальном Codex и облачном Codex через GitHub. Целевой хостинг — VPS для `iam.timuroid.ru`. `.openai/hosting.json` — метаданные прежнего Sites-проекта; их наличие не означает запрос на публикацию в Sites.

## Запуск и проверка

- Node.js 24, `npm ci` для зависимостей.
- `npm run dev` собирает проект и запускает `http://127.0.0.1:4173`.
- `.env` необязателен; настройки также читаются из переменных окружения. Ключ OpenAI нужен только для функций агента.
- После изменения контента или HTML выполните `npm run build` и обновите страницу. CSS и браузерные JS в режиме разработки читаются с диска.
- Перед передачей изменений: `npm run check`, `npm run build`, `git diff --check`. Проверяйте соответствующее поведение; не добавляйте тесты, повторяющие простую правку текста.
- Подробный совместный процесс: `docs/WORKFLOW.md`. Развёртывание VPS: `deploy/README.md`.

## Содержание и визуальный стиль

- Это личный сайт Тимура, а не лендинг агентства. В начале показывайте его роли: руководство AI-разработкой в «Цифровой стали», исследования и преподавание в МГТУ им. Баумана. Сотрудничество следует после знакомства, опыта и проектов.
- Пишите кратко и прямо. По запросу пользователя удалены «За решениями — опыт и любопытство», «Мой путь», «Как я к этому пришёл» и Programmium. Актуальный порядок: знакомство, текущие роли, проекты, повседневная работа с ИИ, сотрудничество, опыт и образование, контакты.
- Публичный контент: `content/site.json`; расширенные серверные знания: `content/agent-knowledge.json`. Демонстрационные кейсы помечайте явно; не выдавайте придуманные результаты, сроки, даты или метрики за факты. Источники логотипов: `content/logo-sources.json`.
- Тёплый светлый фон, бронзово-золотые акценты и глубокий navy; Manrope для основного текста и курсивная Georgia для выразительных заголовков. Живой шар движется автономно с фиксированным центром: указатель плавно меняет освещение, нажатие мягко нарастает и затухает около 2–3 секунд. Не возвращайте скачок скорости на границе элемента, промышленную анимацию и схему «Задача → ИИ → Рабочий инструмент». Уважайте reduced motion и производительность мобильных устройств.
- Голос — основной вход, «Написать» — отдельный удобный чат. Не показывайте чат в voice, не запускайте приветствие. Явно различайте микрофон выключен, подключение, слушание и паузу при ответе. Переход в чат освобождает микрофон.
- Одна панель перемещается между hero, локальным overlay и dock. Нажатие dock раскрывает разговор на текущем месте без прокрутки наверх; возвращение hero в viewport восстанавливает inline. Не показывайте одновременно большой и маленький шар. Темы в чате — текстовая строка. При клавиатуре используйте visualViewport, не допускайте просвечивания сайта.
- Голос Cedar; max_output_tokens 1200 после подтверждённого обрыва на 220. VAD не перебивает ответ; mic приостановлен при ожидании/воспроизведении. «Перебить» отдельно от mic on/off, с response_id барьерами. Disconnected получает 8 секунд на восстановление, подключение 30 секунд. Не утверждайте полную проверку физического голоса на основании protocol/mock тестов.
- Опрос контактов: имя, способ связи, задача по одному; только подтверждённые поля в редактируемую форму. Уже известное не переспрашивайте. Отправка и согласие ручные. Не возвращайте отдельную диктовку «Наговорить».
- По решению пользователя native tick используется через настоящее нажатие на фокусируемый checkbox switch под визуальным микрофонным control. Не подделывайте trusted события и не запускайте импульсы в фоне. Остальные controls используют доступный Vibration API и попытку совместимости. Физический Taptic подтверждается только на устройстве.

## Изменения и секреты

- Начинайте отдельную ветку от актуального `main`. Сохраняйте чужие изменения; не делайте force push. Не ведите одну ветку одновременно с компьютера и из облака.
- Не коммитьте `.env`, API-ключи, пароли, SSH-ключи, базы заявок, аудио, cookies или состояние браузера. Не печатайте их в логах. Настоящий ключ хранится только на сервере или в локальном/облачном окружении.
- Заявки хранятся в SQLite (на прежнем Sites — D1). Отправка формы не рассылает уведомления; не обещайте их без реализации.
- GitHub push сам по себе не развёртывает сайт. Выполняйте публикацию по явному запросу пользователя. На VPS сначала проверяйте существующие службы и домены; изменяйте только ресурсы TIMUROID, сохраняйте данные и резервные копии конфигурации. Не трогайте другие машины.
