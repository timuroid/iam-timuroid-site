# TIMUROID — личный сайт Тимура Кирибаева

Личный сайт Тимура Кирибаева: AI-разработка в «Цифровой стали», исследования и преподавание в Бауманке, проекты и повседневная работа с ИИ. Эксперимент текущей версии — представить этот опыт, дать посетителю познакомиться через сайт или ИИ-агента и проверить интерес к совместным проектам. Эта формулировка восстановлена из исходников и правок пользователя; исходный диалог по shared-ссылке получить не удалось.

На странице — глянцевый тёмно-синий шар, текстовый и голосовой агент, видео «LLM на практике», диктовка и форма связи. Демонстрационные кейсы отмечены явно; реальные результаты и метрики следует добавлять после подтверждения.

Основной репозиторий: **[timuroid/iam-timuroid-site](https://github.com/timuroid/iam-timuroid-site)**. С компьютера и из облачного Codex изменения передаются через него. Код сайта, сервер, шрифты, логотипы, миграции базы и конфигурация VPS находятся в этом репозитории.

## Скачать и открыть в Codex на компьютере

Установите [Git](https://git-scm.com/downloads) и [Node.js 24 LTS](https://nodejs.org/). В терминале выполните:

```bash
git clone https://github.com/timuroid/iam-timuroid-site.git
cd iam-timuroid-site
npm ci
npm run dev
```

Откройте **папку `iam-timuroid-site`** в приложении Codex как существующий локальный проект. Сайт доступен по адресу **http://127.0.0.1:4173**. Остановить сервер можно сочетанием `Ctrl+C`.

Копия `.env.example` с именем `.env` позволяет задать `OPENAI_API_KEY` в редакторе. Для просмотра сайта ключ не нужен; он нужен для агента и диктовки. Сервер также читает настройки из переменных окружения. `.env` и локальные базы исключены из Git. Для отправки изменений в GitHub потребуется авторизация вашей учётной записи с доступом к репозиторию.

После изменения `.env` перезапустите `npm run dev`, чтобы сервер прочитал новые настройки.

## Поддерживать с компьютера и из облака

**[Подробная инструкция: локальный Codex, облачный Codex и синхронизация через GitHub](docs/WORKFLOW.md)**.

В облачном Codex подключите этот репозиторий через GitHub и выбирайте его для задач. Ведите задачи в отдельных ветках, проверяйте изменения и объединяйте их в `main`. Перед началом работы на компьютере получите обновления: `git switch main`, затем `git pull --ff-only`. Одна ветка не должна одновременно редактироваться в двух средах.

Инструкции для самого Codex и правила проекта находятся в [AGENTS.md](AGENTS.md). GitHub хранит исходники; отправка коммита сама по себе не обновляет работающий сайт.

## Где менять проект

| Что изменить | Файл или каталог |
| --- | --- |
| Тексты, опыт, проекты и знания агента | `content/site.json` |
| Структуру страницы | `public/index.html` |
| Цвета, типографику и оформление | `public/styles.css` |
| Живой шар и его отражения | `public/orb.js` |
| Видео и постер занятия | `public/media/` |
| Навигацию, проекты и форму | `public/app.js` |
| Чат и голосовой разговор | `public/agent.js` |
| Диктовку формы | `public/dictation.js` |
| Серверный API | `server/worker.mjs` |
| Сервер Node.js для VPS | `server/node.mjs` |
| Потоковая отдача медиа и перемотка | `server/media.mjs` |
| Структуру базы и миграции | `db/schema.ts`, `drizzle/` |
| Источники логотипов | `content/logo-sources.json` |

Перед передачей изменений выполните:

```bash
npm run check
npm run build
git diff --check
```

`npm run dev` и `npm start` автоматически собирают проект перед запуском. При изменении контента или HTML во время разработки повторите `npm run build` и обновите страницу. Режим разработки сохраняет заявки в `.sites-runtime/preview.sqlite`; обычный Node-сервер — в `data/timuroid.sqlite`. Эти файлы не передаются через GitHub.

## Развёртывание и состояние проекта

Сайт опубликован на **[iam.timuroid.ru](https://iam.timuroid.ru)** на VPS пользователя: Node.js 24, отдельная служба systemd и существующий Caddy с HTTPS. Актуальные пути, обновление и возврат к предыдущей версии — в [deploy/README.md](deploy/README.md). Локальная рабочая ветка — `codex/timuroid-local-setup`; автоматический push и публикация из GitHub не настроены.

`.openai/hosting.json` — исторические метаданные прежнего Sites-проекта. Текущая доставка видео рассчитана на Node.js/VPS: сборка отдельно копирует `public/media` в `dist/media`, а сервер поддерживает HTTP Range для перемотки. Один Worker без Node-обёртки эти файлы не обслуживает.

Ключ OpenAI задаётся только на сервере. Текстовый агент обращается к серверному API, голосовой использует WebRTC и OpenAI Realtime. Микрофон запускается явным действием и освобождается при закрытии. Диктовка добавляет распознанный текст в форму; отправляется он отдельной кнопкой после согласия посетителя. Заявки сохраняются в базе сайта, уведомления в Telegram или email не отправляются. История чата и аудио в базе сайта не сохраняются.

Новое открытие агента начинает чистый разговор. Внутри открытой панели текст и голос сохраняют общий контекст. Три темы сменяются каждые восемь секунд в простое; смена приостанавливается во время ответа, ввода текста и взаимодействия с подсказками. В голосовом режиме нажатие темы продолжает тот же разговор.

Тактильный отклик кнопок использует доступный `navigator.vibrate`. На iPhone настоящий переключатель микрофона `input type="checkbox" switch` получает системный отклик Safari, доступный с iOS 18 ([WebKit](https://webkit.org/blog/15865/webkit-features-in-safari-18-0/#switch)). Программные нажатия на скрытый переключатель не используются. Везде остаётся визуальная реакция шара и поддержка уменьшения движения. Реальная проверка микрофона, Safari, тактильного отклика и мобильной клавиатуры ещё не проведена.
